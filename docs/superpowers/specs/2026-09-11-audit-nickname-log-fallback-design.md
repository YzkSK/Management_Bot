# 監査ログによるニックネーム変更ログ補完 設計

## 目的

Discord の `guildMemberUpdate` が欠落する、または変更前メンバーが partial となる場合でも、監査ログの `MemberUpdate` / `nick` 差分を使ってニックネーム変更ログを残す。

## 背景

現在の `member.nicknameChange` は `guildMemberUpdate` だけから生成される。一方、監査ログ相関は既存のメンバーログに実行者を追記するだけであり、既存行がなければ監査ログのみが残る。実際に 2026-09-11 01:58:17 UTC の監査ログには `nick: Yzk -> Yuzuki` が記録されていたが、対応するメンバーログは存在しなかった。

## 設計

### 通常イベントの partial 対応

`guildMemberUpdate` の旧メンバーが partial の場合、対象メンバーを取得し直して通常処理を継続する。ただし、取得結果は変更後の状態であり変更前ニックネームを再現できないため、差分を確定できない場合はログを生成しない。この経路は partial による不要な欠落を減らすための補助である。

### 監査ログのフォールバック

`MemberUpdate` 監査ログに `nick` の変更が含まれる場合、監査ログ情報に次を含める。

- `before` / `after`: 監査ログの `old_value` / `new_value`。未設定のニックネームは `null` として扱う。
- `previousUserName`: 対象 Discord ユーザーの本来の表示名。初回ニックネーム設定時に一覧見出しの主語として使う。

相関処理では、対象ユーザー・`nicknameChange`・変更後ニックネームを条件に、既存のメンバーログをまず探して実行者を追記する。既存行が見つからない場合だけ、監査ログIDを冪等キーにした `member.nicknameChange` を新規保存する。

### 重複防止と到着順

監査ログ処理は既存の1回・2秒リトライを使う。通常イベントの保存が監査ログより遅い場合は再検索して既存行を相関する。両方の検索で見つからない場合だけ補完ログを作成する。補完ログは監査ログIDをキーにするため、同じ監査ログの再配信でも重複しない。

## 範囲外

- `nick` 以外の `MemberUpdate` フィールドを新しいメンバーログとして表示すること。
- 過去に保存済みの監査ログからの一括バックフィル。

## テスト

- partial な旧メンバーを安全に扱い、誤った差分ログを作らないこと。
- `nick` 監査ログが既存の `nicknameChange` 行に実行者を付与すること。
- 対応行がない場合に、監査ログの before / after で補完ログを作ること。
- 初回ニックネーム設定で `previousUserName` を補完ログに保存すること。
