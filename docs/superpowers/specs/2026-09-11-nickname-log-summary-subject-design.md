# ニックネーム変更ログの一覧主体名 設計

## 目的

ニックネーム変更ログの一覧見出しを、変更者と変更対象の関係に応じて自然に表示する。自己変更では、変更前のニックネームを主体として表示し、初回設定ではニックネーム設定前の元の表示名を使う。

## 表示ルール

| 条件 | 一覧見出し |
| --- | --- |
| 実行者IDと対象ユーザーIDが一致する | `変更前ニックネーム（未設定なら変更前の表示名）がニックネームを変更しました` |
| 実行者IDが未判明 | 上記と同じ自己変更形式 |
| 実行者IDと対象ユーザーIDが異なる | `実行者が対象者のニックネームを変更しました` |

詳細を展開したときの `ニックネーム: 旧値 → 新値` 表示は維持する。

## データ設計

`nicknameChange` ログにのみ、任意の `previousUserName` を追加する。これはイベント発生時点の旧 `GuildMember.displayName` を保存するスナップショットである。

```ts
previousUserName: oldMember.displayName
```

自己変更時の一覧主体は、次の優先順位で決める。

1. `changes.nickname.before`（変更前ニックネーム）
2. `previousUserName`（初回ニックネーム設定前の表示名）
3. 既存の対象ユーザー表示名の解決結果

これにより、旧ニックネームが `null` の場合でも「未設定」を主体名にせず、当時の元の表示名を使える。表示時にDiscord APIの現在名を問い合わせる方式は採らないため、過去ログの表示が後から変わらない。

## 互換性

既存の `nicknameChange` ログは `previousUserName` を持たない。表示は既存の対象ユーザー表示名へフォールバックし、読めなくならない。

## テスト

- 共有ログスキーマが `previousUserName` を許可する。
- ハンドラが旧 `displayName` を `previousUserName` に保存する。
- 自己変更は旧ニックネーム、初回設定は `previousUserName`、他者変更は従来の実行者・対象者表現を使う。
- `previousUserName` を持たない既存ログが現在のフォールバック表示を維持する。
