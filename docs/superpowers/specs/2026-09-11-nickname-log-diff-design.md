# ニックネーム変更ログの差分表示 設計

## 目的

Discord ギルド内のニックネーム変更について、変更前と変更後の値をダッシュボードのログ詳細で確認できるようにする。

## 対象範囲

- `guildMemberUpdate` から生成する `member` カテゴリの `nicknameChange` ログ。
- ダッシュボードのログ詳細を展開したときの差分表示。
- ニックネームを設定する変更と、未設定に戻す変更の両方。

過去に保存済みのログを移行・補完すること、一覧見出しの文言を変更すること、Discord 通知チャンネルの本文を変更することは対象外とする。

## 設計

`member` のログスキーマに、任意の `changes` フィールドを導入する。`nicknameChange` を記録する際は、次の形で差分を保存する。

```ts
changes: {
  nickname: {
    before: string | null,
    after: string | null,
  },
}
```

Discord.js の `GuildMember.nickname` はニックネーム未設定時に `null` を返すため、そのまま保存する。空文字列へ置換しないことで、「未設定」と空文字列を混同しない。

ダッシュボードでは既存の `summary.changes` 表示を再利用する。`nickname` を表示名「ニックネーム」に追加し、`null` は既存の値整形ルールに従い「未設定」と表示する。旧値は取り消し線、新値は通常表示、間に矢印を置く。

## データフロー

1. `guildMemberUpdate` が旧・新 `GuildMember` を渡す。
2. 旧新の `nickname` が異なる場合、ハンドラが `changes.nickname.before/after` を含む `nicknameChange` エントリを生成する。
3. 共有スキーマで検証されたエントリが既存のログ保存経路を通る。
4. ダッシュボードがログを取得し、展開詳細の既存差分コンポーネントで表示する。

## エラー処理と互換性

- `oldMember.partial` の更新は、現在と同様に不確実な差分を記録しない。
- `changes` を持たない既存の `nicknameChange` ログは有効なままとし、差分表示を省略する。
- `changes` は機微情報として扱わない。ニックネームは現在の `userName` スナップショットと同じ閲覧権限で表示される。

## テスト

- 共有スキーマが `nickname` の文字列／`null` 差分を許可することを検証する。
- メンバーハンドラが設定・解除それぞれで正確な `before` と `after` を生成することを検証する。
- ログ一覧詳細が `nickname` を日本語ラベルで、未設定値を含む既存の差分UIとして描画することを検証する。
